# ProofSight Domain Ontology & Ubiquitous Language

> **Domain Authority**: This document establishes the authoritative ubiquitous language, core entities, friction taxonomies, terminal states, and deterministic invariants for ProofSight — Autonomous Visual Evidence Agent. All User Stories, Technical Tasks, Interfaces, and Policy Rules must conform strictly to these terms.

---

## 1. Ubiquitous Language & Core Entities

| Entity / Concept | Type | Definition & Invariants |
| :--- | :--- | :--- |
| **InspectionSession** | Aggregate Root | Authoritative inspection lifecycle managing observations, component findings, retry limits, audit logs, and final verdict. Identified by `inspectionId: UUID`. |
| **KitTemplate** | Entity | Versioned definition of an equipment kit (e.g. `technician-kit-a104`), defining expected components, quantities, reference images, and region layouts. |
| **ComponentRequirement** | Value Object | Individual required item within a kit (`componentId`, `name`, `quantity`, `isMandatory`, `expectedRegion`, `referenceFeatureDigest`). |
| **Observation** | Entity | A visual capture instance containing raw image metadata, OpenCV quality assessment (blur, exposure, coverage), alignment status, and capture timestamp. |
| **VisualMeasurement** | Value Object | Deterministic OpenCV measurements for a region: Laplacian blur variance, histogram exposure level, feature match count, coverage ratio, and occlusion indicator. |
| **ComponentFinding** | Entity | Current state of a component requirement within a session (`componentId`, `status`, `evidenceScore`, `supportingObservationId`, `regionBoundingBox`). |
| **AgentGuidance** | Value Object | Targeted observation recommendation generated by the reasoning agent (`actionType`, `targetComponentId`, `guidanceMessage`, `rationale`). |
| **DeterministicPolicyEngine** | Domain Service | Stateless authority enforcing business rules BR-01 through BR-15, validating transitions between component and session states. |
| **HumanOverride** | Value Object | Recorded supervisor intervention containing `reviewerId`, `timestamp`, `reason`, `overriddenStatus`, preserving automated finding history. |
| **InspectionVerdict** | Value Object | Final session determination (`PASSED`, `NEEDS_MORE_EVIDENCE`, `REVIEW_REQUIRED`, `FAILED`, `CANCELLED`) with cryptographic evidence hash. |

## 2. Problem Taxonomies / Friction States

Every obstacle encountered during visual inspection is deterministically mapped to one of these taxonomies:

1. `F01_IMAGE_QUALITY_DEFECT`: The captured photograph is unusable due to severe blur (Laplacian variance < threshold), extreme over/underexposure, or poor framing.
2. `F02_PARTIAL_OCCLUSION`: The required item is partially hidden, shadowed, or obstructed by an adjacent object, preventing unambiguous verification.
3. `F03_PERSPECTIVE_MISALIGNMENT`: The camera perspective is skewed beyond the homography tolerance, preventing registration with the reference kit layout.
4. `F04_UNRESOLVED_AMBIGUITY`: Visible visual measurements cannot confirm component identity or presence; requires targeted follow-up view.
5. `F05_CONFIRMED_DEFECT_OR_ABSENCE`: Targeted follow-up observation confirms that a mandatory item is absent or damaged.
6. `F06_UNPRODUCTIVE_LOOP`: Inspection attempt count reaches maximum threshold without resolving ambiguities; escalates to supervisor.

## 3. Canonical Terminal States

### Component Finding Lifecycle States

| State | Definition & Invariants | Permitted Transitions |
| :--- | :--- | :--- |
| `NOT_OBSERVED` | No usable observation recorded yet for this requirement. | `UNRESOLVED`, `VERIFIED`, `SUSPECTED_MISSING` |
| `UNRESOLVED` | Evidence is ambiguous or partially obscured; observation is insufficient. | `VERIFIED`, `SUSPECTED_MISSING`, `ESCALATED` |
| `SUSPECTED_MISSING` | Expected item not detected in adequate compartment coverage. | `VERIFIED`, `CONFIRMED_MISSING`, `ESCALATED` |
| `VERIFIED` | Verified by deterministic OpenCV measurements and policy rules. | `UNRESOLVED` (only upon conflicting evidence) |
| `CONFIRMED_MISSING` | Absence confirmed by authorized secondary capture or supervisor. | Human remediation or review |
| `ESCALATED` | Manual supervisor review required due to persistent ambiguity. | Supervisor determination |

### Inspection Session Lifecycle States

| State | Definition & Invariants |
| :--- | :--- |
| `CREATED` | Session initialized with a valid versioned kit template; no captures yet. |
| `IN_PROGRESS` | Initial capture uploaded and undergoing OpenCV analysis. |
| `ASSESSING` | OpenCV metrics computed; agent evaluates evidence and policy checks. |
| `NEEDS_MORE_EVIDENCE` | Unresolved mandatory item detected; agent issued targeted camera guidance. |
| `PASSED` | All mandatory items verified with valid visual evidence; policy satisfied. |
| `REVIEW_REQUIRED` | Retry limit reached, conflicting evidence, or unresolved mandatory item. |
| `FAILED` | Confirmed missing mandatory item or policy breach. |
| `CANCELLED` | Session aborted by inspector or supervisor. |

## 4. Deterministic Business Rules (BR-01 through BR-15)

The AI reasoning model only observes and drafts guidance; the deterministic Policy Engine governs and enforces all state transitions:

| Rule ID | Rule Name | Required Deterministic Behavior | Basis / Authority |
| :--- | :--- | :--- | :--- |
| **BR-01** | Approved inspection template | An inspection session must reference an existing versioned kit template. | Configuration Policy |
| **BR-02** | No unsupported approval | Never mark a required component `VERIFIED` without supporting visual measurements. | Quality Invariant |
| **BR-03** | Unknown is not missing | Insufficient visibility or occlusion must produce `UNRESOLVED`, never `SUSPECTED_MISSING`. | Decision Integrity |
| **BR-04** | Evidence before assertion | The agent must attempt a targeted additional observation before escalating ambiguity. | Operational Efficiency |
| **BR-05** | Adaptive guidance | Each follow-up request must specify the affected component and targeted corrective action. | Ergonomic UX |
| **BR-06** | Image quality gate | Reject images failing configured blur (variance < 100) or exposure thresholds (<15 or >240). | Perception Integrity |
| **BR-07** | Maximum retries | Stop automated loop after configured attempt limit (default: 3) and escalate to supervisor. | Cost & Loop Prevention |
| **BR-08** | No fabricated confidence | Never convert language-model output into uncalibrated mathematical confidence scores. | Algorithmic Safety |
| **BR-09** | Mandatory item enforcement | An inspection cannot transition to `PASSED` while any mandatory item remains unverified. | Release Governance |
| **BR-10** | Human control | Authorized supervisors can override findings, recording reviewer ID, timestamp, and reason. | Operational Audit |
| **BR-11** | Evidence traceability | Every capture, measurement, agent prompt, and transition is immutably appended to audit log. | Traceability Standard |
| **BR-12** | Separation of authority | Agent proposes observations; deterministic Policy Engine authorizes state transitions. | Architectural Invariant |
| **BR-13** | Duplicate evidence | Recaptured images that add no new geometric or feature information do not increase scores. | Information Gain Rule |
| **BR-14** | Conflicting evidence | Contradictory findings between observations trigger reinspection or supervisor escalation. | Consistency Gate |
| **BR-15** | No unsafe autonomy | The agent cannot authorize equipment release outside customer approval policy. | Safety & Compliance |
